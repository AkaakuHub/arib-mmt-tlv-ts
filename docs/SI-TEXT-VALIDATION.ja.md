# TSのSI文字列における漢字集合指定の確認

2026年10月21日、漢字集合へ戻る指定の後も英数として解釈する不具合を修正しました。2バイト集合の指定先G0（`ESC $ ( F`）を受理し、漢字集合の最終バイト`0x42`を漢字として復号します。入力文字列の置換や、別の文字コードへの再解釈は追加していません。

`decodeSIText(Uint8Array.from(bytes))`の結果を、同じバイト列で比較しました。

| バイト列（16進数） | 修正前 | 修正後 |
|---|---|---|
| `0f 1b 28 4a 41 1b 24 28 42 46 7c 4b 5c` | ＡＦ｜Ｋ＼ | Ａ日本 |
| `0f 1b 28 4a 41 1b 24 42 46 7c 4b 5c` | Ａ | Ａ日本 |
| `0f 1b 28 4a 41 1b 24 28 39 46 7c 4b 5c` | ＡＦ｜Ｋ＼ | Ａ日本 |

先頭の`0f`でG0をGLへ呼び出し、`ESC ( J`で英数集合を指定して「Ａ」を出します。その後、各形式で2バイト集合を指定し、`46 7c 4b 5c`の「日本」を復号する例です。

保存済みのBS4K録画TSをTSReaderへ入力し、EITの短形式イベント記述子を実際のdecoderへ渡しました。NHKとQVCの計5番組で、従来の全角英数・記号列が日本語タイトルへ戻ることを確認しています。例として「［４Ｋ］【連続テレビ小説】ブラッサム（１６）第４週「岩国と、共に」🈖🈑」と「［４Ｋ］　ＱＶＣインフォメーション🈖」を取得しました。番組説明も日本語として復号しています。

`npm run build`は成功しました。この確認はSIの番組名・説明の復号を対象とし、字幕や映像に焼き込まれた文字、ブラウザの描画、実機の受信状態は検証していません。
